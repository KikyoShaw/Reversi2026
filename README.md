# 黑白棋 · Reversi

独立的 **Tauri 2 + Vue 3 + TypeScript + Rust** 黑白棋桌面游戏，提供人机、本地双人与局域网双人对弈。采用标准 8×8 棋盘、八方向翻子规则，界面使用清晰的大字号、合法落点和翻子反馈。

棋盘、黑白棋子与图标由本项目的 CSS/SVG 绘制，音效使用 Web Audio 合成；运行不依赖其他项目、素材目录、账号或云端服务。

## 开发与打包

环境要求：

- Node.js 20 LTS 或更新版本，npm。
- Rust stable；Windows 使用 MSVC 工具链。
- Visual Studio 2022 Build Tools 的“使用 C++ 的桌面开发”，以及 Windows SDK。
- Microsoft Edge WebView2 Runtime。

在本项目目录执行：

```powershell
npm install
npm run tauri dev
```

开发端口为 `127.0.0.1:1440`。`npm run tauri dev` 会启动前端和 Rust 游戏服务；单独执行 `npm run dev` 只运行网页，无法使用原生对局与联机服务。

需要 Windows 程序和安装包时执行：

```powershell
npm run tauri build
```

预期输出：

- 程序：`src-tauri/target/release/reversi2026.exe`。
- NSIS 安装包：`src-tauri/target/release/bundle/nsis/`。

首次安装/构建需要下载依赖和打包工具。当前仅交付源码与资源，未安装依赖，未运行构建、类型检查、lint、测试或应用；尚无运行验收结论。

## 对弈规则

- 棋盘为 8 行 8 列，坐标使用 A～H、1～8。
- 初始中央四子为 D4、E5 白子，E4、D5 黑子，双方各两枚；始终由黑方先行。
- 每一步必须落在空格，且沿横、竖或斜线夹住至少一枚对方棋子。被夹住的棋子全部翻为本方颜色。
- 一步可以同时翻转多个方向。射线必须以本方棋子封住，遇到空格或边界不算夹住。
- 一方无合法落点时自动跳过，由另一方继续；玩家不能自行跳过有合法着法的回合。
- 双方都没有合法落点时结束，即使棋盘尚未填满。按棋盘上的实际子数判胜负，相同则为平局；空格不计入任何一方。

标准开局黑方可下 C4、D3、E6、F5。黑方下 D3 后应为黑 4、白 1。

## 三种模式

**人机对弈**：选择执黑或执白，提供入门、进阶、挑战三档。电脑先手也会等待点击开始。

**本地双人**：两位玩家共用一台电脑轮流落子，适合面对面切磋和研究局面。

**局域网双人**：一方创建房间，另一方输入 IP 地址及端口加入。双方分别执黑白，房主统一裁决落子、时限和协商。

默认人机模式、玩家执黑、进阶难度，音效及合法落点开启，每步不限时。

## 开始、暂停和计时

- 初次打开、新建对局或修改对局规则后，均先进入“待开始”，不会自动计时或落子。
- 点击 **开始** 才能落子，并在需要时启动电脑搜索。
- 点击 **暂停** 会冻结当前剩余时间、阻止落子并取消电脑思考。暂停期间可以查看棋盘、规则和棋谱。
- 点击 **继续** 沿用暂停前的余额，轮到电脑时重新安排搜索，不补满本步时限。
- 可设置每步 0～600 秒，0 表示不限时；超时判当前行棋方负。超时胜负与棋盘子数多少无关。
- 自动跳过后，实际继续行棋的一方获得新一步的完整时限。
- 对局结束后不能继续，需要悔棋或重新开局。

Rust 使用单调时钟裁定截止时间，界面倒计时用于显示；开始与暂停在不限时模式下同样有效。

## 棋盘与辅助操作

- 直接点击合法格落子；开启提示后会显示合法落点，悬停可观察该步的翻子范围与数量。
- 键盘可在棋盘中用方向键移动焦点，Enter 或 Space 确认落子。弹窗和输入框保留自己的键盘行为。
- 最近一步带标记，已确认的翻子执行动画；重复快照、音效开关等操作不会重复落子或重播该步。
- 点击 **提示** 搜索推荐位置，仅高亮建议，不自动代下；棋局变化后的旧提示会失效。
- 双方实时显示棋子数量、执色、行动状态和每步剩余时间。
- 坐标棋谱记录行棋颜色、落点、翻子和自动跳过情况。

电脑与提示均在后台计算。新局、悔棋、暂停或断线会取消旧任务，提交搜索结果前再次核对局号与回合。

## 悔棋

- 本地双人撤回最近一次落子，包括该步产生的自动跳过。
- 人机退回玩家上次落子之前，撤回之后所有电脑连续行动，正确处理跳过回合；电脑先手且玩家还未下过棋时不能悔棋。
- 悔棋保留当前运行/暂停状态，并为退回后的那一步重置完整时限。
- 终局后悔棋进入暂停，需要点击继续才能恢复行棋。
- 联机悔棋需对方同意，默认撤回最近一次落子。

## 电脑难度

电脑使用迭代加深 Alpha-Beta 搜索，评价角位、位置、行动力、前沿棋子和不同阶段的子数价值。

| 难度 | 常规深度上限 | 思考预算 |
| --- | --- | --- |
| 入门 | 2 层 | 约 150ms |
| 进阶 | 4 层 | 约 500ms |
| 挑战 | 8 层 | 约 1500ms |

剩余空格较少时尝试搜索到终局，但受时间预算限制，只采用已经完成的搜索结果。设置有限步时时，思考预算同时服从当前剩余时间；取消或过期搜索不能落到新局面。

策略用于休闲对弈，不宣称专业引擎级棋力。

## 局域网房间

1. 双方电脑位于同一局域网，启动兼容版本的客户端；同一电脑的两个实例也可通过 `127.0.0.1` 连接。
2. 房主在房间窗口选择执色、时限和端口，默认游戏端口为 `9529`。开发端口 `1440` 与游戏端口不同。
3. 访客填写房主局域网 IP、端口及昵称加入，执房主相反颜色。
4. 双方准备后，由房主点击开始。Windows 防火墙如提示，请允许当前专用网络通信。

`0.0.0.0` 表示监听地址；其他电脑应填写房主实际局域网 IP。可通过 Windows `ipconfig` 查询 IPv4 地址。

房主控制开始、暂停和继续；访客同步显示阶段。悔棋和重新开局需要对方同意，请求 30 秒未答复或棋局变化后失效。协商未处理时不能切换暂停状态；运行中的计时和合法落子仍继续，暂停中的计时保持冻结。

同意重开后双方回到待开始，需重新准备。连接中断时暂停并保留棋盘、棋谱和剩余时间，可离开房间转为本地双人，手动继续；访客通过公开棋谱重建完整可悔棋状态。首版没有自动重连，重新创建/加入房间使用新局。

协议采用产品标识 `reversi2026`、版本号、4 字节大端长度前缀和 JSON，单帧最大 64 KiB，包含握手、心跳、有界队列和连接代次校验。房主验证执色、轮次、合法落点和请求编号。功能面向局域网，不提供公网匹配或在线账号。

## 设置与资源

昵称、模式、执色、难度、时限、音效和落点偏好保存在应用配置目录中的 `settings.json`。Windows 通常位于 `%APPDATA%\com.kikyoshaw.reversi\`；下次启动恢复设置，但不会自动恢复上次网络连接或未完成棋局。

项目不内置指向其他游戏的 GitHub 入口，也不要求初始化 Git。源代码采用 Apache-2.0，见 [LICENSE](LICENSE)；依赖沿用各自许可。

## 手动验收建议

- 检查标准开局四个合法黑方落点，以及 D3 后黑 4、白 1。
- 检查多方向翻子、边角、空射线、被占格和非法落子。
- 构造单方跳过、双方均无着、未满盘终局和子数相等平局。
- 检查连续电脑行动后悔棋，棋盘、棋谱、轮次和子数一起恢复。
- 检查电脑执黑先手等待开始、暂停余额冻结、继续不补满，以及旧 AI 与旧提示失效。
- 检查短步时超时、不限时、终局悔棋后暂停和新局等待开始。
- 两个客户端检查双方准备、颜色分配、落子、协商同意/拒绝、请求失效、断线暂停和转本地保留历史。
- 在最小窗口下检查字号、按钮、弹窗滚动、键盘选位与焦点恢复。
